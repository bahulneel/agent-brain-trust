# Dialogue: questions, inquiry, and confirmations

Use during **Grounding** (readings, inquiry, value constraints, grounding statement) and anywhere the protocol requires user or writer input.

## Questions

- Ask only what **blocks** understanding or the next protocol step — not curiosity for its own sake.
- Respect per-member inquiry limits (e.g. up to **2 questions** per member per inquiry round when the suite specifies it).
- After answers, return to **readings** or revised readings when the suite requires it.

## Confirmations

- Do not advance past **Pre-readings guest drafting** (when the suite opens EW/DC slots), **Readings**, **Value constraints**, **Grounding statement**, or **Trajectory** without explicit **user/writer confirmation** when the suite says so.
- If confirmation is missing, summarise state and ask for it briefly.

## Tools

If you have **user interaction** (chat, prompts, UI): use it for confirmations and clarifications instead of inventing answers.

If you do **not** have interactive tools: state what you would ask, what assumption you are making, and invite the user to correct it in the next message.

## Tone

Neutral, concise, procedural — the Moderator’s voice for process; cohort voices stay in-character for substance.
